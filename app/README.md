# 此刻 / Cike — 使用与技术说明

一个本地优先的时间记录工具。核心交互只有一条规则：**点击类型即开始计时，再次点击即结束**。

本文档面向使用者与二次开发者，包含操作说明、数据模型、构建方式与限制说明。
版本历史见仓库根目录的 `CHANGELOG.md`。

---

## 1. 运行方式

### 1.1 浏览器

```bash
python tools/serve.py 8788 app
```

| 入口 | 地址 |
| --- | --- |
| 本机 | `http://127.0.0.1:8788/` |
| 同一局域网内的手机 | `http://<本机 IP>:8788/` |

服务器对每个响应设置 `Cache-Control: no-store`，因此刷新即可获取最新代码；
若浏览器仍显示旧内容，请检查 Service Worker 是否持有旧构建（见 6.3）。

### 1.2 安卓 APK（完全离线）

安装 `dist/cike-1.2.3.apk`。首次安装时系统会要求允许「安装未知来源应用」。

申请权限：`VIBRATE`、`FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_SPECIAL_USE`、
`POST_NOTIFICATIONS`。**未申请 `INTERNET`**，应用在系统层面无法发起网络请求。

### 1.3 从源码构建 APK

需要 JDK 17+、Android `build-tools`（含 `aapt2`、`d8`、`zipalign`、`apksigner`）、
`platforms/android-34`，以及 `pip install pillow`（用于生成各密度图标）。

```bash
python android/build_apk.py
```

可用环境变量：`CIKE_BT`（build-tools 目录）、`CIKE_PLATFORM`（平台目录）、
`CIKE_JDK`（JDK 路径）、`CIKE_BUILD`（中间产物目录）。版本号读取自
`android/AndroidManifest.xml`。详见 `android/README.md`。

## 2. 界面与操作

### 2.1 此刻

- **状态卡**：空闲时显示起始提示；计时中显示类型名、实时时长、开始时间与暂停/继续/停止按钮。
- **分组卡片**：二级结构中的分组。卡片头部显示今日合计与播放键（直接记为分组本身）；
  展开后为子类型胶囊，可点击、可长按拖动排序。
- **类型网格**：不属于任何分组的类型直接显示为大格。
- **24 小时墨带**：横向表示一天的分布。按住空白处拖动可补记一段（吸附到 5 分钟），
  拖动过程中右上角实时显示区间与时长；点击已有段可编辑该记录。
- **首次使用提示卡**：仅在没有记录时出现。

### 2.2 记录

按天分组，显示时间区间、备注、标签与时长。支持按类型名、备注、标签搜索。
跨零点的记录会按天切分并标注「跨天」，以保证两天合计正确。
点击任意一行进入编辑；修改结束时间时右侧实时预览时长。

### 2.3 统计

顶部胶囊切换 **今天 / 本周 / 本月 / 今年**，标题行显示合计、与上一等长周期的对比、
以及最集中的时段。

| 区块 | 说明 |
| --- | --- |
| 主图表 | 饼图 / 环形 / 条形三种画法，可按 **分组** 或 **类型** 汇总 |
| 周期图 | 分母为所选区间的总时长（24 小时 / 168 小时 / 当月天数 / 全年），空白部分单独统计 |
| 四个指标 | 日均、条目数、最长一段、未记录；日均按已过天数计算 |
| 分布 | 今天按小时、本周按星期、本月按天、今年按月，按分组颜色堆叠 |
| 一周节奏 | 7 行（周一至周日）× 6 列（每 4 小时），颜色取该格中占比最高的类型 |
| 排行 | 前 10 项，含占比、子类型明细、与上一等长周期的增减 |
| 目标 | 进度条；「不超过」类目标超额时标红 |

所有数字来自同一次区间裁剪结果，避免不同卡片之间口径不一致。

### 2.4 我的

类型（两级结构、颜色、图标）、目标（每天/每周/每月/每年 × 达成/不超过）、
外观（主题、语言、动效、点按震动、撤销停留时长、一天从几点开始）、
数据（导出 JSON / CSV、导入、清空）、关于（版本与构建号）。

## 3. 数据模型

| 表 | 字段 | 说明 |
| --- | --- | --- |
| `types` | `id, name, color, icon, parentId, order, isGroup, counts` | `parentId` 非空即为子类型；层级最多两级 |
| `records` | `id, typeId, start, end, pausedMs, pausedAt, note, tags` | `end == null` 表示进行中；同一时刻最多一条 |
| `goals` | `id, name, period, mode, typeIds, targetMin` | `period`: day/week/month/year；`mode`: reach/limit |
| `kv` | `k, v` | 设置项（主题、语言、撤销时长等） |

三条与时间相关的约定：

1. **只保存时间戳**。进行中的记录不写入累计值；界面每秒用 `Date.now()` 求差，因此切到后台、
   锁屏或标签页被挂起都不会造成累计漂移。
2. **暂停是冻结，不是相加**。暂停时记录 `pausedAt`，聚合时以 `pausedAt` 作为右端点。
3. **重叠自动让位**。补记或编辑产生的重叠区间会裁剪既有记录（保留左右两端，必要时拆成两段）；
   若被裁剪的是正在计时的记录，则在插入点断开，计时不中断。

撤销通过**整表快照**实现：每次结构性变更前深拷贝 `types/records/goals`，撤销时整表回写，
保证与操作前逐字节一致。快照栈上限 20 层。

## 4. 设置项

| 设置 | 取值 | 说明 |
| --- | --- | --- |
| 主题 | 深色 / 浅色 / 跟随系统 | APK 中「跟随系统」由原生桥提供真实系统值 |
| 语言 | 中文 / English / 跟随系统 | 切换时会重命名仍为默认名的类型，可撤销 |
| 动效 | 开 / 关 | 关闭后过渡使用 `animation: none`，而非缩短时长 |
| 点按震动 | 开 / 关 | Web 端使用 `navigator.vibrate`，APK 中由原生桥执行 |
| 撤销停留 | 3 / 5 / 8 / 10 秒 | 影响提示条与撤销按钮的存活时间 |
| 一天从几点开始 | 0–6 点 | 影响「今天」的边界，适合凌晨活动的作息 |
| 最短记录时长 | 默认 0 | 低于该阈值的记录不落库 |

## 5. 通知（仅 APK）

开始计时后，前台服务在通知栏显示常驻通知：

| 状态 | 折叠态 | 展开态 |
| --- | --- | --- |
| 计时中 | 一行：类型名 + 系统计时器 | 三行：类型名 / 计时器 / 说明 |
| 暂停 | 一行：类型名 + 静态时长 | 三行：类型名 / 静态时长 / 「已暂停 · …」 |

秒数由系统 `Chronometer` 推进，应用不参与刷新；暂停时切换为静态文本，避免「秒数停了但看起来仍在走」。
通知为 `VISIBILITY_PUBLIC`，锁屏可见。点击通知回到应用。
若通知被系统关闭或降级为静音，「我的 → 通知」会显示状态并提供前往系统设置的入口。

## 6. 技术说明

### 6.1 技术栈与约束

零依赖：原生 ES Modules + 手写 CSS，无打包步骤。`app/` 目录可直接作为静态站点部署，
也可原样放入 APK 的 `assets/www/`。

### 6.2 APK 容器

`MainActivity` 使用 `WebView` 加载 `https://cike.local`，并通过
`WebViewClient.shouldInterceptRequest` 将该主机的请求映射到 `assets/www/`。

不使用 `file://` 的原因：`file://` 属于不透明源，IndexedDB 不可用；
`https://` 为安全上下文，存储能力完整，且由于不申请网络权限，请求不会离开设备。

### 6.3 缓存与离线

`sw.js` 采用**网络优先、失败回退缓存**：在线时始终获取最新代码，离线时使用上一次缓存。
调试时若怀疑命中旧模块，先清除站点数据（DevTools → Application → Storage → Clear site data），
否则可能正在测试上一次构建。构建号（`我的 → 关于 → 构建 cike-vNN`）可用于判断当前运行版本。

### 6.4 调试参数

| 参数 | 作用 |
| --- | --- |
| `?demo=1` | 无记录时铺一周示例数据 |
| `?lang=en` / `?lang=zh` | 临时切换界面语言（不写入设置） |
| `?native=1` | 模拟 APK 原生桥：震动打日志、导出走浏览器下载 |
| `?motion=off` | 关闭动效 |

### 6.5 存储

IndexedDB 数据库 `cike-db`，对象仓 `types / records / goals / kv`。
若 IndexedDB 不可用（隐私模式等），自动降级为 `localStorage`。
连接可能在系统回收或另一标签页升级时失效，此类写入会重建连接并重试一次。

### 6.6 国际化

`app/js/i18n.js` 维护词典与规则表，渲染完成后按文本节点翻译，并用 `MutationObserver`
覆盖后续插入的抽屉与提示条。除精确匹配外还有两类通用规则：

1. 按 ` · ` 拆分逐段翻译（如 `本周 · 已记 1%`）；
2. 将结尾括号视为补充说明，单独翻译后拼接（如 `未记 167h 0m（之后 98h 1m 还没到）`）。

用户数据（类型名、备注、标签）不参与翻译；仅当类型名等于内置默认名时，切换语言才会同步改名。

## 7. 进程与功耗

- 浏览器与 APK 的界面每秒刷新一次文本，其余时间无定时器。
- APK 的通知秒数由系统计时器推进，前台服务不持有唤醒锁。
- 无后台同步、无网络请求、无第三方 SDK。
